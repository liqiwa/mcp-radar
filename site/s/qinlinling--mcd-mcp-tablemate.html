About mcd-mcp-tablemate

多人协作点餐为主线、同桌食光票根为传播出口的麦当劳 MCP 参赛作品。 一句话：先把这顿饭点好，再把这次相聚留下。

3—8 人聚餐时，最难的不是找最低价，而是「谁想吃什么、谁不能吃什么、预算够不够」的反复沟通。 麦麦同席把这件事变成三张桌子：

1. 每人填三档心愿（必须要 / 最好有 / 不要），「不要」是硬约束； 2. 系统用真实门店菜单 + 官方核价给出三套策略不同的方案（人人有期待 / 整单更划算 / 一起尝点新）， 每套都说明「谁的心愿被满足、谁被调整、为什么这么取舍」； 3. 确认后一键生成同桌食光票根——带撕裂线的纸质票根，可直接下载分享， 默认不含金额、门店详址和订单号。

- 发起人：办公室工作餐、项目庆功、宿舍拼单、朋友聚餐的组织者——不想在群里反复接龙统计「谁吃什么、谁不加辣、预算多少」。 - 参与成员（通常 3—8 人）：想用结构化心愿（必须要 / 最好有 / 不要）代替长段文字，并看到自己的诉求被明确处理的人。 - 分享对象：聚餐成员及用户主动选择的外部受众——票根默认脱敏，分享由用户自己决定。

前提：Python 3.10+（无需任何第三方包），以及可用的麦当劳 MCP token。

仓库根目录就是项目根目录，所有命令都在根目录执行。docs/ 中少数文档写于开发工作区 （当时项目位于 mmtx/ 子目录），其中出现的 mmtx/xxx 与这里的 xxx 指同一文件。

浏览器打开 http://127.0.0.1:8848 即可。首页有「填入标准演示场景」按钮，一键填好 4 人示例。

后 4 个是开发期脚本，需要 node 依赖（作品本身运行不需要）： npm i -D jsdom puppeteer-core canvas，或设置 MMTXDEVMODULES 指向已有这些包的 nodemodules。 截图脚本还需要本机 Chromium 内核浏览器（Edge/Chrome），可用 MMTXBROWSER 指定路径。

① 建聚餐：打开首页 → 点「填入标准演示场景」→「查门店」→ 选第一家 → 设共同预算 200 元 → 「创建聚餐」。

② 各自说心愿：逐位填「必须要 / 最好有 / 不要」。例：小北要麦辣鸡腿堡、阿岚不吃辣、大可要巨无霸、糖糖不要牛肉。 系统会把口语匹配到菜单（例如「鸡块」→「麦乐鸡」），匹配不上的如实告诉你。

③ 看三套方案：人人有期待 / 整单更划算 / 一起尝点新。每套都给出整单官方核价、人均、 每件餐品归谁、每个人的心愿处理结果，以及「为什么这么取舍」。价格一律来自官方核价，页面顶部标数据时点。

④ 调整并确认：可增删餐品、改归属、改数量，每次改动都会重新核价（旧价立即作废）。 分账表按「归属 + 共享分摊 − 优惠分摊」计算，底部校验合计是否等于整单。确认只代表「保存为方案」，不下单。

⑤ 生成票根：可勾选展示字段、改昵称、加合照/每人一句话/下次约定，选竖版/方图/竖屏导出。 票根默认隐藏订单号、门店详址、个人预算与分摊。

⑥ 下次再聚：确认方案后可勾选成员「同意保存口味」→ 下次在第 1 步一键带入 → 系统按当前菜单重新查、重新核价，不沿用旧价格。

完整五步口播稿见 docs/演示脚本.md；两档尺寸的逐屏截图见 docs/screenshots/。
