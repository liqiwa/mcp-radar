About wechat-local-mcp

让 Claude Code 直接读你电脑上自己的微信聊天记录。 只在本机读写，不联网、不上传、不注入微信进程。

一句话：微信把库加密了，密钥只在运行中的微信进程内存里；本工具把密钥读出来、把库解开、再通过 MCP 协议交给 Claude。

工具 干什么 典型用法 --------- listrecentchats 最近有消息的会话，按活跃时间倒序 「我最近跟谁聊得多？」 readchat 看某个人 / 某个群的聊天记录 「看看我和导师这周的对话」 searchchats 全库搜关键词（压缩存的消息也会解开再搜） 「我在哪提过这个项目？」 voicetranscripts 只取某个会话的语音转写，按时间正序，带 epoch 「把这段对话里我说的话补回来」 refreshdata 重新取密钥并解密，看新消息前要刷一次 「刷新一下」 clearcache 删掉本工具生成的明文缓存 「把缓存清了」

readchat 的 who 参数支持备注名 / 昵称 / 群名 / wxid，并且支持片段模糊匹配；匹配到多个时会列出候选让你选。

voicetranscripts 是给「和别的微信索引搭配用」准备的：别人把语音统一存成 [语音]， 这个工具只挑语音出来、只解析 packedinfodata，比重读整个会话便宜得多。 返回里每条都带 epoch（秒级时间戳），可以直接和别的库的 createtime 对上。

先说结论：如果你只是想要一个能用的产品，本项目不是最优选。GitHub 上已经有做得更全的同类项目。

项目 ★ 平台 路线 和本项目的区别 ------:--------- stkoecn/im-mcp 83 Windows + macOS 同样是「读进程内存取密钥 → 解密本地库」，29 个工具，有 FTS5 全文索引 功能全面得多，还支持钉钉。想直接用就选它 bojieli/greenbubbles 423 仅 macOS Rust + Swift，读本地库 Windows 上用不了 lich0821/WeChatFerry 6.8k 仅 Windows 注入 DLL 进微信进程，能收发消息 是机器人框架，不是历史阅读器；绑定特定微信版本；注入有账号风险 JettChenT/wechat-mcp 47 — — 2025-01 之后没再更新，属于微信 3.x 时代

im-mcp 的 29 个工具和整篇功能列表里，检索「语音 / voice / 转写 / SILK / audio」全部 0 命中。 而语音在微信里占比极高——本项目实测一个账号 23,718 条语音。不处理等于整段对话是空的。

本项目从 packedinfodata 的 protobuf（字段 5 → 2）里取出微信自己做的转写配在消息里， 秒数从 voicelength 取。取不到时明确告诉你「没有转写」，而不是丢一个 [语音] 就完事。

证据等级：检索过对方 README，也读过对方 adapters/media.py、parser.py、tools/keytool.py 的源码。 源码里「语音」只作为消息类型标签出现（34: "语音"、17: "实时语音"）， 没有 packedinfodata、没有转写提取、没有音频解码。这一条是可以核实的。

7 个文件 1,739 行 Python，没有框架、没有构建步骤、没有子模块。 想搞明白「微信的库到底是怎么加密的、Claude 是怎么拿到聊天记录的」，从这个仓库读进去比读一个大项目快得多。
