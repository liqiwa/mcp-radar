About mcp-sprawl-audit

Every Claude Code, Codex or Grok session starts its own copy of each local MCP server in its config. With many sessions open, that adds up to hundreds of processes and gigabytes of memory, most of it waiting for a tool call that never comes.

This is an agent skill and a single Python script that measures that on your machine and writes a plan. It is read-only: it changes no config and touches no process. It reads the names of env vars and headers, never their values. From a command line it prints only a package name or a script's file name, and from a URL only the scheme and host, because the rest can carry keys.

Why this exists tells the story of 57 agent sessions running 646 MCP server processes on one laptop, and how sharing three servers over localhost took them from 19.5 GB to 301 MB.

Or run the script yourself. It needs only Python (3.11+ to read Codex and Grok TOML).

- Running agent sessions per agent, and every local MCP server copy they hold: processes, resident memory, idle npx or uvx launchers. - How often each server was actually called, from each agent's own session logs. - One action per server: share (serve one copy over HTTP on 127.0.0.1), use-hosted, keep, per-project, remove?, plugin (bundled, only its author can change it), check (unknown: the agent looks it up) or ok. - Flags: servers holding a credential, versions not pinned to an exact release, and one server configured under two names (which may be two accounts, so it never assumes one copy can serve both).
