About xiaohongshu-mcp-reliable

一个面向 AI Agent 自动化的小红书 MCP 可靠性分支，基于 xpzouying/xiaohongshu-mcp。

上游项目已经提供了登录、浏览、搜索、发布、评论、点赞、收藏与通知等完整能力；这个分支重点处理另一类问题：当浏览器超时、进程重启或模型重复调用时，如何避免重复发布、重复评论和回复错楼。

这是非官方社区分支，与小红书及上游维护者无隶属关系。自动化操作可能受站点规则和页面变化影响，请遵守适用的服务条款与法律，并先使用测试账号验证。

我从真实的发布超时与评论回复问题出发，提出并定义了异步任务、幂等去重、不确定状态、精确评论定位和浏览器串行等产品规则，降低 AI Agent 重复发布、重复评论与回复错楼的风险。

我负责提出需求、确定产品方案与验收结果；代码实现和自动化测试由 AI 完成。完整过程见 中文产品案例：如何让 AI Agent 的写操作更可靠。

浏览器自动化的失败并不总等于操作没有发生。比如提交按钮已经生效，但客户端在看到成功提示前超时；如果 Agent 把超时直接当失败并重试，就可能产生重复内容。

这个分支把写操作建模为可查询、可恢复的任务，并明确区分“确认失败”和“结果未知”。核心原则是：不确定时先核实，不盲目重发。

- 图文发布、顶层评论、评论回复改为异步任务，调用后立即返回任务 ID。 - 支持显式 idempotencykey；未提供时，对相同请求在 10 分钟窗口内自动去重。 - 任务持久化到本地；服务重启后恢复排队任务，并把执行中断但无法确认的任务标记为 unknown / uncertain。 - 回复必须使用 commentid 精确定位，不使用 userid 猜测目标。 - 回复操作记录页面阶段、网络请求状态和服务端接受/拒绝证据，区分 confirmed、rejected、blocked 与 uncertain。 - 同一条评论的在途任务及近期不确定/已确认任务会触发冷却，防止换正文或换幂等键绕过去重。 - 全局浏览器槽位把浏览器操作串行化，避免多个自动化页面争抢同一账号状态。 - 推荐列表、搜索结果和用户主页默认返回精简字段与数量上限，减少 Agent 上下文占用。 - 登录二维码会话只保留一个，新请求会结束旧会话，避免后台浏览器堆积。 - MCP 与 HTTP 路由不暴露删除 Cookie 的入口，降低模型误清登录状态的风险。 - 修复发布页标题输入框因页面刷新而失效的问题；保留上游最新版的功能引导关闭逻辑。

操作 提交工具 查询工具 关键终态 --- --- --- --- 图文发布 publishcontent getpublishstatus succeeded, failed, unknown 顶层评论 postcommenttofeed getcommentstatus confirmed, unknown 评论回复 replycommentinfeed getreplystatus confirmed, rejected, blocked, wrongtarget, uncertain

queued 和 running 表示尚未结束。unknown / uncertain 表示操作可能已经到达站点，调用方应先检查实际页面，不能直接重试。

要求 Go 1.24 或更高版本。完整的 Docker、客户端和登录说明可参考上游文档。
