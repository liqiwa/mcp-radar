About livewall

Livewall is a live status board your AI agent writes while it works.

An agent running a long job has two bad options: go silent, or spam you with status messages. Livewall is the third. The agent sends a small JSON board spec and a browser renders it live. That spec might be a progress bar for a migration, a table of test results, a log tail, a fleet status wall. None of it needs per-use-case UI code.

Every block type on one board — light and dark, desktop and phone. The images are generated by scripts/makescreenshot.py, so they cannot drift from what the client actually renders.

- Watch the job instead of asking about it. The agent programs the board once and updates it as it works, so the numbers on screen come from the agent, not from you scraping logs. - No dashboard to build or maintain. The board is whatever the agent describes in a small JSON document; there is no per-use-case frontend. - Many jobs, many tabs. Each agent or session owns a named board, and the client shows them as tabs. - Boards are ephemeral by design. A board is a one-off surface for one running operation. It lives on a TTL, then it is gone. That is the point: there is no state to migrate, back up or clean up between runs.

1. The agent calls an MCP tool with a board spec: title, status, blocks, optional tab and TTL. (The bundled CLI drives the same API from a shell, for callers that are not an MCP host.) 2.
