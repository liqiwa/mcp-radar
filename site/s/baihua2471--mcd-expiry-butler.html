About mcd-expiry-butler

一个真实使用麦当劳 MCP 的 WorkBuddy Skill：只读查询你的优惠券与积分，按预算给出最多两套用餐方案， 金额全部经过官方 calculate-price 试算，并明确告诉你哪些权益不值得为了消耗而额外花钱。

- 卡包里攒了一堆券，每次点单前都要翻半天的人 - 被「今日到期」提示催着下单，事后发现并不划算的人 - 有预算约束（比如这周只吃一次、只花 30 元），想吃得明白的人

做： - 列出快到期权益（默认 7 天窗口，可调）与有效期、剩余天数 - 按门店 + 渠道筛选真正可用的券 - 对每个候选方案调用官方价格试算，给出已验证应付金额 - 输出最多两套方案 + 推荐理由 + 不建议使用清单 + 未确认条件 - 积分与现金分开展示（不做任何兑换比例换算）

不做（第一版红线）： - ❌ 领券 / 兑换 / 抽奖 / 下单 / 取消订单 / 付款 / 改地址 - ❌ 估算或编造价格；试算失败就显示失败 - ❌ 推断缺失的到期时间；缺就写「到期信息未提供」 - ❌ 假设券可叠加、跨门店或跨渠道通用

1. 已在 https://open.mcd.cn/mcp 用手机号登录并激活 MCP Token 2. 已把麦当劳 MCP 配到 WorkBuddy：

配置位置：~/.workbuddy/mcp.json（WorkBuddy 的用户级自定义 MCP 配置）。 配好后需在连接器管理 → 自定义连接器中信任该服务，并重启 WorkBuddy。 mcp-config.example.json 只含 ${MCDMCPTOKEN} 占位符，WorkBuddy 不会自动展开， 请手工替换，且不要把替换后的文件提交到任何仓库。

安装到 ~/.workbuddy/skills/mcd-expiry-butler（加 --project 可装到当前项目）。 重新执行同一条命令即可更新。

它会先问清三件事（预算 / 就餐方式 / 门店），然后查数据、试算价格、生成结果页。

输出的页面顶部有醒目横幅：「样例数据，非实时账户结果」。 真实查询失败时不会静默切换为样例数据。

1. 我这周只准备吃一次麦当劳，预算 30 元，看看有什么快到期的权益值得用。 2. 帮我看看哪些券 3 天内到期，在深圳科技园到店吃，预算 25 元。 3. 我的积分快过期了，用麦麦权益到期管家看看要不要换，别推荐我为了积分多花钱。

场景 期望 ------ 没有优惠券 建议不使用，说明原因 没有到期字段 显示「到期信息未提供」，不输出剩余天数，不推断 已过期权益 进入「不建议使用」，不参与推荐 所有方案超预算 不推荐，列出实际金额与差额 门店/渠道不适用 排除并说明原因 价格试算失败 不输出估算金额，标记为失败 积分将过期但缺兑换商品信息 不给积分建议，标注缺失 真实模式失败 不混入演示数据，模式标识保持 real 正常场景 最多两套，价格均为「已验证」且可追溯

真实联调记录见 docs/REALRUN2026-10-09.md（只读，已脱敏）。

- 第一版只做查询与试算，不会替你领券、下单或兑换。 - 券的适用范围以门店维度接口结果为准；卡包概览里的券不一定在该店可用。 - 积分接口不返回具体到期日期，只有「本月/下月将过期」数量。 - 早餐券等带时段的券，只在对应时段可用；当前时段不符时不会推荐。 - 价格是查询那一刻的结果，实际下单可能因库存、时段变化而不同。 - 餐品、价格、权益与供应状态以麦当劳官方渠道实时结果为准。
