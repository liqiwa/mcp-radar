About afas_ai_mcp_connector

A Model Context Protocol server for AFAS Profit that every user logs in to with their own AFAS account. You deploy it once for your organisation; assistants such as Claude Code, Claude Desktop or Cursor connect to it by URL, send the user through the AFAS login, and then read data through your GetConnectors with exactly the rights that user has in AFAS.

- AFAS OAuth 2.0, per user. Authorization code flow with PKCE against an AFAS app connector. There is no shared token: every call reaches AFAS with the access token of the user who made it. - Read-only by default. Insert, update and delete tools exist only when AFASALLOWWRITES=true. - AFAS tokens stay on the server. They are stored encrypted; MCP clients only get tokens issued by this server. - Nothing bundled. Connectors and fields are discovered from AFAS metainfo, and write payloads are checked against the UpdateConnector schema before anything is sent.

The OAuth 2.0 flow follows AFAS's published documentation and has been tested against a live AFAS environment. Start on an AFAS test environment all the same.

The server sits between two OAuth 2.0 conversations. Towards MCP clients it is an authorization server; towards AFAS it is a confidential client of your app connector. A tool call is only forwarded when the caller's MCP token maps to a stored AFAS login, and AFAS decides what that user may see.

You need an AFAS environment where you can create an OAuth app connector, a host with Docker, and a hostname with TLS in front of it. The steps below are the short version of Getting started.
