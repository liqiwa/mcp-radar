About contextmap

Local AST-powered Context Map & MCP Server for AI Coding Assistants Stop burning tokens blindly and stop your AI from breaking 3 screens when you ask to edit 1.

When building apps with AI (Cursor, Claude, Windsurf, Antigravity, Gemini, etc.), three things happen constantly: 1. Token burn: Every small request makes the AI scan dozens of irrelevant files or re-audit things you already resolved. 2. Domino regressions: Tweaking one file silently breaks dependent screens or removes permission checks. 3. Recurring AI blind spots: Modals closing when you highlight text and release the mouse outside (onClick instead of onMouseDown), users stuck on stale cache without Ctrl+F5, expensive N+1 database loops, timezone bugs, and forms losing unsaved input.

ContextMap runs 100% locally on your machine (your code never leaves your computer), parses your codebase directly from the AST using Tree-sitter with incremental hash caching, and exposes surgical context to your AI via MCP (Model Context Protocol) + a clean bilingual visual dashboard (🇺🇸 EN / 🇧🇷 PT).

🏆 The "Smart Plan ➔ Cheap Execution" Workflow 1. Plan with a top model + ContextMap (Zero-Edit Rule): ContextMap never modifies your code — it isolates the exact domino effect, God Nodes (PageRank), code skeletons, and pending checklist items so a top model builds a rock-solid plan using a fraction of the tokens. 2. Execute with a cheaper/faster model: Hand the surgical plan to a lighter model to implement safely.
