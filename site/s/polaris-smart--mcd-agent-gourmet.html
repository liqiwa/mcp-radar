About mcd-agent-gourmet

多 agent 协作帮你点最省的麦当劳 营养师+预算师+口味师分工，owner 审批后安全下单

痛点 我们帮你解决 ------ "怎么点最省？" 预算师枚举最优组合，暴露凑单陷阱 "券快过期了！" 主动提醒沉默成本（即将过期的券=白扔的钱） "怎么吃健康？" 营养师分析营养构成，标记超标项 "选择困难症" 三 agent 分工推荐，owner 一键审批

市面上的麦当劳 Skill 都在回答"怎么点最省/怎么点最健康"。 我们回答一个更完整的问题："一群 agent 怎么协作帮你点餐"。

正如麦当劳官方所说："帮助 AI Agent 连接麦当劳服务"、 "集成点餐、领券等核心能力，快速构建拥有麦当劳能力的专属 AI Agent"—— 我们在此基础上，加入多 agent 协作与治理层： 不是"一个 agent 帮你点餐"，而是"一群 agent 协作，owner 审批后安全下单"。

官方能力 我们的实现 ------ 智能点餐 多 agent 协作点餐（营养师+预算师+口味师+owner 审批） 日历活动抢先知 预算师主动提醒"券快过期"（沉默成本） 优惠券周周领 预算师枚举最优组合（暴露凑单陷阱）

Agent 角色 职责 --------- 营养师 健康守门员 分析营养构成，标记超标项 预算师 省钱专家 计算最优组合，暴露凑单陷阱 口味师 美食顾问 推荐搭配，考虑个人偏好 owner（你） 最终决策者 审批方案，确认下单

- 需求账：你想吃什么（口味/营养/份量） - 预算账：你愿意花多少钱（预算/券/积分） - 审批链：三 agent 出方案 → owner 审批 → 安全下单

mcd-coupon-strategist mcd-agent-gourmet（我们） --------- 视角 单 agent 省钱 多 agent 协作 决策 算法排序 角色分工+owner 审批 输出 最优方案 多方案对比+推荐理由 治理 无 两本账+审批链

需求账： - 你想吃什么（口味/营养/份量） - 你的预算上限 - 你的券/积分存量

预算账： - 当前方案实付金额 - 券的沉默成本（即将过期的券） - 积分价值（积分兑换 vs 现金支付）

维度 单 agent（如 mcd-coupon-strategist） 多 agent（我们） --------- 决策模式 算法排序 → 输出最优解 角色分工 → owner 审批 输出形式 单一方案 多方案对比+推荐理由 冲突处理 算法内部权衡 显式标注冲突点（如"营养超标但最便宜"） 治理 无 两本账+审批链 可解释性 "这是最省的" "营养师推荐 A（健康），预算师推荐 B（省钱），你选哪个？"

1. 绝不猜测价格 —— 所有金额来自 MCP calculate-price 返回 2. 先确定门店 —— 价格与券可用性均绑定门店 3. 多 agent 意见必须呈现 —— 不强行统一，如实展示差异 4. owner 审批是硬门 —— 任何下单操作必须经 owner 显式确认 5. 主动暴露凑单陷阱 —— 为用券加购导致实付上升必须指出 6. 不确定就说不确定 —— 缺货/价格缺失如实说明 7. 不构成营养或医疗建议 —— 仅作为参考信息呈现

所有 MCP 响应经 mcdadapter.py 统一转换后才进业务逻辑—— 全员唯一的"分→元"换算点，防止单位混乱。
