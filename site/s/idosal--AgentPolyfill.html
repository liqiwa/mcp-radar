About AgentPolyfill

Polyfills for agent protocols. Bring more of MCP to the clients you already use. Plugins and extensions add Apps, Skills, Events, Server Cards and ARD; the table below shows which run in each host.

An early proof of concept. It works today, and it has real gaps. Events, Skills and Apps can't reach servers behind OAuth yet, Apps runs only in Claude Code, and a few spec rules can't be met from a plugin. Each gap comes from what the host APIs expose, and small, generic changes to those APIs would close them: what hosts would need to change.

MCP grows through extensions now: Apps, Skills, Events, Server Cards. A server can adopt one in a day, but every host has to build each one itself, on its own schedule, so a new extension can sit unused for months. A polyfill closes that gap from the outside. It implements one published extension's client side as a plugin or host extension, follows that extension's spec (any exception is listed and can be switched off), and steps aside once the host ships its own. Servers don't change at all.

We want this to be an open community around open specs: anyone can use these extensions in the host they have, bring a polyfill to another host, or propose a new extension, without waiting on one company's roadmap.

- If you use one of the supported hosts, see its install steps below. - If you build, the create-polyfill and design-extension skills and the contract every polyfill here meets are your starting point.
