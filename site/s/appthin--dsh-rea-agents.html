About dsh-rea-agents

把 REA（rea-agents）固定在一个确切版本的 DeepSeek Harness 插件： 从配置档里那份副本启动它的 MCP 服务（207 个逆向分析工具），只有你在插件卡片上按下「更新」，版本才会前进。

为什么要固定版本，而不是沿用 npx -y rea-agents@latest？

- 跨会话结果无法对比。 静默升级可能改变工具的参数结构、Evidence 处理方式或默认值，而你这侧没有任何记录说明它发生过。 - 被投毒的版本会立即生效。 没有审查环节，也没有可回退的版本号。 - 「昨天还好好的」无法证伪。 你分不清是目标变了，还是工具变了。

对一个专门产出「你要据此推理的证据」的工具来说，随时拉最新版是错误的默认值。本插件把它反过来： 启动时读磁盘上那份固定副本，新版本只在你看到版本号并主动点击之后才会到来。

插件 → dsh-rea-agents：版本、安装状态与操作按钮，就长在插件自己的卡片上。

检测最新版本：走配置档自己的 registry（pnpm view），不另开网络通道。

版本要求： DSH = 0.1.6-alpha.1 且 = 22.19.0；rea-agents 自己声明 ^22.19.0 ^24.11.0 =26.0.0，不匹配时页面会在安装前给出提示。

Desktop 的 profile 由 Electron 应用独占管理。 dsh plugin --profile desktop … 会被 CLI 直接拒绝（error: profile "desktop" is managed exclusively by the Electron application）， 这是 DSH 的硬性约束，不是本插件的问题。Desktop 请在应用内安装。

装完重启 dsh（或等待 profile 热重载），在 插件 → dsh-rea-agents 的卡片上就能看到控件。

插件只负责把 REA 装好、盯住版本、开好 MCP 连接。安装 REA 本体需要在卡片上再点一次「安装」， 它会写入依赖、执行 pnpm add rea-agents@ --save-exact，并记录固定了什么。

打开 dsh，进入 插件 → dsh-rea-agents，卡片上应出现「REA 版本」区块。没有出现时的排查顺序：

1. 确认装进了正在使用的 profile（dsh plugin --profile web ls 查看清单）； 2. 重启一次 dsh —— 浏览器半边的模块表在启动时构建； 3. 打开 http://127.0.0.1:/rea-agents/diagnose，按输出判断卡在哪一步（见下节）； 4. 仍无法解决时，附上 /diagnose 输出提交 issue。

卡片上有版本号，只说明插件在跑，不说明 MCP 这条链路通了。想确认工具真的可用，把下面这句交给 DSH 里的助手：

列出你的 mcprea 工具，调用 mcpreabinarysession，参数为空 {}，看看返回什么。

助手能列出一批 mcprea 开头的工具，并且 binarysession 返回一份会话信息 （而不是「没有这个工具」），就说明 REA 的工具已经注册到模型侧了。

卸载插件不会删除已装的 rea-agents；想一并清掉，先在卡片上点「卸载REA」，再移除插件。 分析引擎与本插件无关，任何时候都不会被删除。
