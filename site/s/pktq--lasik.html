About lasik

Static deobfuscation for anti-agent hardening. LASIK removes BLA protection layers so coding agents and analysis tools can read the real program.

0.3: structural detection. Protection is identified by what it does, not by its names, so renamed builds heal too. Benchmark

LASIK reads a protected build, proves which parts are protection (opaque predicates, encrypted strings, decoy code, tamper checks, binary padding, prompt-injection text), removes them, and writes a clean copy. It never runs the input.

- 1,262× fewer tokens on the public BLA CrackMe corpus: about 21 million down to 17 thousand. - Proof-based. A transform runs only when LASIK can prove it preserves behaviour. Unprotected files come back byte-identical. - Structural detection. Protection is recognised by behaviour, not identifiers; a renamed-build benchmark runs in CI. - Static only. No eval, no sandbox, no WebAssembly instantiation; safe on hostile input. - Prompt-injection firewall for text planted to steer the model. - 21 formats: JavaScript and TypeScript bundles, inline HTML, WebAssembly, Electron ASAR and fuses, source maps, Python and .pyc, native ELF/PE/Mach-O, Bun, SQLite, safetensors and GGUF, PCAP, JVM, .NET, BEAM, EVM, PTX, ZIP/APK/DEX, plists, IL2CPP and UF2 firmware. - Name recovery where the program still publishes the original name (exports, imports); neutral names elsewhere. - Agent integration: CLI, MCP server for Claude Code, Cursor, Codex and seven more, and a library API.
