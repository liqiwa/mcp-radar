About mcd-nutrition-expert

麦当劳营养膳食专家（McDonald's Nutrition Diet Expert）

一个基于 SP 矩阵理论 的个人饮食搭配可视化选型工具，基于麦当劳官方 MCP Server 打通「营养计算 → SP 选型 → 套餐推荐 → 门店点餐 → 领券下单 → 健康记录」的完整闭环。

SP 矩阵选型界面 —— 156 个餐品的真实分布，金色十字是按你的身体档案推导出的目标点

指标 数值 指标 数值 ------::---:------: 官方 MCP 工具 35 营养数据条目 160 门店菜单条目 98 菜单 SP 覆盖率 88% 四象限分布 主力 47 / 解馋 46 / 填充 53 / 双刃 10 动态阈值 P50×0.6 + P75×0.4 REST 接口 14 前端第三方依赖 0

人群 典型场景 本项目帮他解决什么 --------- 体重管理期人群（减脂 / 塑形） 加班到八点，只能吃麦当劳，不知道怎么点不超热量 按档案算出单餐 626 kcal 目标，直接给出结构合理的套餐（如 555 kcal 低钠方案） 健身增肌人群 练完腿想吃麦当劳，需要高蛋白但不想钠爆表 SP 矩阵的「双刃区」精确标注高蛋白高钠餐品，配合钠上限控制摄入量 有代谢指标关注需求的人 需要控钠（高血压、肾脏指标等日常管理） 钠负担作为独立维度参与打分，高钠组合会被显著降权 不想做功课的普通用户 站在点餐机前 30 秒做不了决定 「一键求解」直接给出 3 套可执行方案 + 象限角标标注，决策时间 以下所有数值均为真实接口实测输出（POST /api/recommend），非示意。

示例 1 · 减脂期午餐（女 28 岁 / 165cm / 58kg / 中等活动 / 减脂）

💡 系统的价值不止于「给出一套餐」，更在于同时告诉你取舍在哪：方案一蛋白最足但钠到 94%，方案二钠只有一半但蛋白少 11g —— 用户可以自己权衡，而不是在「不知道热量」和「只知道热量」之间二选一。

示例 2 · 增肌日午餐（男 25 岁 / 178cm / 82kg / 高强度活动 / 增肌）

💡 注意方案三：系统没有藏起这个超标项。它在 warnings 里主动把超出量算给你看，而不是给一个看起来很美的组合 —— 这正是「可解释」的含义。

痛点 具体表现 本项目的解法 --------- 不知道该吃多少 全天目标 1800 kcal，不知道单餐该占多少 Mifflin-St Jeor + FAO/WHO 活动系数算出全天 TDEE，再按单餐份额（34%）折算单餐目标 不知道该点哪个 菜单近百个条目，看得见的热量标签为零 160 个餐品全量营养数据 + SP 矩阵四象限定位 不知道哪套搭得值 套餐名看不懂，勾起来才发现全是糖和油 结构角色模型（主餐/小食/饮品/甜点）+ 多目标约束求解 不知道自己吃过了什么 吃完就忘，热量缺口无从谈起 SQLite 每日记录 + 体重趋势 + 象限分布可视化

经典 SP（Sweet Point）矩阵用「竞争强度」与「市场地位」划分战略象限。迁移到饮食选型，映射为两个营养密度维度：

SP 原始维度 饮食映射 计算方式 业务含义 ------------ X 轴（吸引力） 营养密度 (蛋白质g + 碳水g) / (热量/100) 每 100 kcal 能带来多少克营养 Y 轴（强度） 钠负担 钠mg / (热量/100) 每 100 kcal 带来多少钠负担
