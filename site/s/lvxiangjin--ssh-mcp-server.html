About ssh-mcp-server

让 ZCode / Claude Code / Codex 等任何 MCP 客户端安全地登上你的服务器执行命令、传文件、跑任务—— 而服务器的 22 端口，从头到尾不需要对 AI（或互联网）开放。

- 🚪 AI 与服务器物理隔离——AI 只认识网关的 443 端口；目标机 22 端口防火墙只对网关放行，AI 所在的网络被攻破也摸不到服务器 - 🧰 六个 MCP 工具 + 两个 GB 级流式端点——执行命令、后台任务、上传下载一个端口全搞定，3GiB 文件恒定内存直达 - 🔐 为"AI 会犯错"设计的安全模型——命令黑名单硬拦、高危命令二次确认、敏感路径双拦、防爆破双维计数、全员审计，详见安全设计

手动 SSH / Xshell 传统堡垒机(JumpServer / 商用堡垒机) ssh-mcp-server ------------ 为谁设计 人类敲键盘 人类运维的会话审计 AI Agent 自主执行 AI 怎么用 ❌ 无法接入 😩 Web UI/交互式会话，AI 难驱动 ✅ MCP 原生协议，配置一次，对话即运维 部署重量 — 数据库 + 容器编排 + 多组件 一个可执行文件 + 一个 config.json 服务器暴露面 22 对用户网络开放 协议网关，较重 22 只对网关放行，公网仅 443 一个口 危险命令拦截 无 会话录像（事后追责） 事前拦截：黑名单 + 高危二次确认 权限模型 账号即权限 4A 集中管控 Token 服务器白名单 × OS 低权限账号，双层限制 凭据轮换 手动改密码 静态或 AD/LDAP HMAC 按天自动轮换，每人独立 secret 文件传输 scp 手动 闪传/网盘中转 3GiB 流式直传，md5 校验，恒定内存 成本 — 企业级授权 / 硬件 开源免费

一句话：堡垒机管的是"人干了什么"，ssh-mcp-server 管的是"AI 能干什么、不能干什么"。它不替代堡垒机——很多团队把它部署在堡垒机之后，作为 AI 专属的那一层。

工具 干什么 ------ listservers 列出该 Token 有权访问的服务器（白名单外的看不见也不存在） runcommand 执行 shell 命令，返回 stdout/stderr/退出码；支持 cwd、background 后台执行、confirm 高危复核 checkjob 查询后台任务状态/退出码/输出尾部（状态落目标机，网关重启不丢，7 天自动清理） killjob 终止后台任务（防 PID 复用误杀） uploadfile SFTP 上传（≤5MB，自动建父目录、原子覆盖、返回 md5） downloadfile SFTP 下载（自动识别文本/二进制，附 md5 校验）

- POST /upload：GB 级文件流式上传，默认上限 3GiB 可调更大，恒定内存，返回远端 md5 - GET /download：不限大小流式下载，响应头 X-Md5 / X-File-Size 先行供校验

其他内建能力：执行超时、输出截断（保头 60% + 尾 40%，防撑爆 AI 上下文）、SSH 并发上限、连接失败自动重试。

任何支持 MCP 的客户端都能接：ZCode、Claude Code、Codex、Cursor、Cline…… 配置一次，之后所有运维都是"说人话"。

「看下 web1、web2 的磁盘占用，超 80% 的把 /var/log 下 7 天前的日志清了」
