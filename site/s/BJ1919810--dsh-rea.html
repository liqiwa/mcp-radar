About dsh-rea

技能来自 morluto/rea（MIT）。本仓库只是把它包装成 DSH 插件。

- REA MCP 服务 —— 207 个逆向分析工具（Ghidra / IDA / jadx / apktool / frida / adb / pcap / 固件 / 浏览器 / Electron / 托管代码 …） - REA 的三个工作流技能 —— reverse-engineer-anything（含 6 篇 references）、rea-tool-design、rea-changelog-update

--profile desktop 是 GUI 用的 profile；TUI 用户改成 --profile tui。 装完在插件页会出现 dsh-rea 这一项，那个开关就是总开关。

方式一用的是 pnpm 的 github: spec，作者未实测 DSH 的供应链策略是否放行； 装不上就用方式二。已实测的只有：Windows x64 + DSH Desktop + REA 6.5.0 + 方式二。

本插件不安装任何引擎（和 REA 本身一样）。REA 只是适配层，引擎缺了对应工具就会报 providerunavailable。常用组合：

用途 需要自备 ------ 原生 PE/ELF 静态分析 Ghidra 12.1.x + JDK 21+（或自备 IDA，见 REA 文档） APK 资源 / DEX apktool、jadx-headless-mcp 0.7.1 的 -all.jar 真机 / 模拟器 Android platform-tools（adb）

本插件不写死任何路径。REA 的 MCP 服务继承 DSH 进程的环境，所以先把变量设成用户/系统环境变量，再启动 DSH：

不设也能装上：插件会正常安装、MCP 服务也能启动，只是对应工具会以 capabilityunavailable 失败，并在提示里点名该设哪个变量（实测：未设 REAAPKTOOLCOMMAND 时，inspectapktoolclient 直接返回「apktool launcher was not found … Set REAAPKTOOLCOMMAND to an absolute apktool launcher」）。 设完变量需要重启 DSH（它只在启动时读环境）。
