About litemcp

La lib MCP la plus légère en mémoire et la plus rapide au monde.

Stateless · socket bindé · Streamable HTTP uniquement (POST/SSE) · zéro runtime async

📦 Crate officiel : crates.io/crates/litemcp · 📖 Docs : docs.rs/litemcp

Installation · Démarrage rapide · Tutoriel · Stack · Concepts · Configuration · Sécurité · Protocole · FAQ · Client

La plupart des serveurs MCP sont des services : un programme qui s'installe, charge un gros framework et tourne à côté de votre application. LiteMCP fait l'inverse : c'est une bibliothèque Rust. Vous écrivez quelques lignes, vous appelez .serve(), et un vrai serveur MCP tourne dans votre programme — avec les threads standards du langage, sans runtime async, sans framework HTTP. Seule dépendance pour le JSON : serde.

- Une CLI qui veut exposer deux ou trois outils, sans embarquer un framework web ; - Un test unitaire qui a besoin d'un vrai serveur MCP qui écoute sur un port — sans installer tokio ; - Un binaire embarqué (edge, IoT), où chaque mégaoctet et chaque dépendance compte ; - Un agent qui lance cinquante serveurs MCP en même temps : chaque mégaoctet de RAM et chaque demi-seconde de démarrage se multiplie par cinquante.

1. Streamable HTTP uniquement. Un seul transport : un socket TCP bindé ; chaque message est un POST /mcp auto-suffisant, la réponse arrive en application/json ou en flux SSE (text/event-stream, request-scoped). Pas de session, pas d'initialize obligatoire, pas de flux permanent. C'est la spec 2026-07-28, à la lettre. 2. Zéro runtime async au cœur. std::net::TcpListener, un thread par connexion.
