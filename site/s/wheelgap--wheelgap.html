About wheelgap

Find the Python dependencies that have no prebuilt wheel for your target platform, before your Docker build does.

Point it at your lockfile and the platforms you ship to (ARM servers, Alpine images, Windows on ARM, free-threaded Python 3.14t). It tells you which packages pip or uv will have to compile from source, and which can't be installed at all.

📊 New: wheel coverage for the top 5,000 PyPI packages, by platform and Python version, updated nightly.

📖 Documentation: wheelgap.github.io/wheelgap, with a reference for every flag, input format, config key and output format.

Run either one in a project directory. It finds uv.lock, pylock.toml, poetry.lock, pdm.lock, Pipfile.lock, requirements.txt or requirements.lock on its own (and, after 0.9.0, pixi.lock). Getting started walks through a first run.

Write your defaults down once in pyproject.toml (every key); command-line flags still win:

Not sure what to put there? After 0.9.0, wheelgap --suggest-targets reads the platforms your CI and Dockerfiles already name and suggests these lines (how).

cell meaning --- --- ✓ a compatible wheel exists, so the install is fast ● source no wheel, only an sdist, so it compiles at install time (needs a compiler, headers, time) ✗ missing no wheel and no sdist, so the install fails – not installed on this target (environment markers exclude it, or the target selects another resolution) ✓ bundled no wheel on PyPI, but Pyodide ships its own build (with --pyodide-lock)
