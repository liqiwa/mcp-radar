About calendarpit

A local calendar service for development and repeatable tests. Build calendar integrations without a real Google account, provider credentials, or an external database.

Status: the documented scope is implemented locally. Includes user/calendar/event management, Google-compatible event APIs and free/busy, local OAuth, watch notifications, fixture/reset controls, and masked request history. Compatibility is intentionally limited; unsupported features return explicit errors. See compatibility.

https://github.com/user-attachments/assets/11db212a-89c9-4a04-8ff2-9711595e2f98

Calendarpit 0.9.5 is available through Docker, Homebrew, and GitHub Releases.

Open . The API, local OAuth, and admin UI share one origin. No Google credentials, environment file, or external database is needed. See installation for Compose, standalone downloads, networking, and updates.

Contributor setup, including the docs preview, lives in docs/.

From a source checkout prepared using the development guide, in another terminal:

Open , connect a calendar, and approve a test user. Create an event, inspect busy intervals, start a watch, update/delete events, and revoke and reconnect. The default sample date is October 19, 2026. The admin UI shows external changes as soon as the server saves them.

The built-in test client is sample-app / local-sample-secret, with callback http://127.0.0.1:4175/callback. The sample overrides authorization, token, user-info, Calendar API, and revocation endpoints and blocks real Google requests. See Connect your app for consuming-app configuration.
