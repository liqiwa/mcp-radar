About pvewarden

Agent-safe patching of Proxmox VE guests over MCP.

pvewarden lets an AI agent keep your Proxmox VMs and containers up to date. It works with Claude Code or any other MCP client. The agent checks pending updates, takes a snapshot, installs, reboots and verifies services. It never gets a shell or root. It can only call a small set of tools, and Proxmox and the server decide what it may do, not the prompt.

Status: v0.1, the first release. Tested on Proxmox VE 9 with Debian 12/13 and Ubuntu 22.04/24.04/26.04 guests, containers and VMs. Feedback and issues are welcome.

Risk What pvewarden does ------ The agent touches guests it should not It only sees guests in the pvewarden pool. Updates need the Proxmox tag pvewarden-update and reboots need pvewarden-reboot. Only you set the tags. The agent gets a shell On guests, the server's SSH key is bound to a forced command that accepts a handful of fixed command words (check, status, upgrade-security, …). No shell, no port forwarding. A compromised guest reaches others Every guest has its own SSH key and accepts only that one. Whatever address a guest reports, the server cannot be sent to another guest. A stolen token unlocks Proxmox The Proxmox API token has a role limited to the pool. It can see guests, take snapshots, roll back and power-manage them. It cannot create, delete, reconfigure or reach the host. A bad update breaks a guest A snapshot comes first, automatically. If the snapshot fails, nothing is installed. The agent "solves" a problem its own way Rollback, snapshot deletion and updates without a snapshot need your click
