About mouseketool

Before you build something new, find out whether it already exists.

When you tell your coding agent you want to build a new tool, app or library, mouseketool searches GitHub for projects that already do it. It checks them for real: their health, their license, and the code behind each README's claims. Then it answers with a verdict against your requirements: reuse, adapt, use as a base, or build from scratch.

- An MCP server does the mechanical work and makes no judgment: - many GitHub searches in one call; - repository inspection: README, files, activity, releases, issues, contributors and license, plus plain health signals; - file reads. - An Agent Skill teaches your agent the method: 1. separate the must-haves from the nice-to-haves; 2. search from several angles; 3. inspect the mature candidates; 4. confirm in the code what the verdict relies on; 5. answer verdict first, with pros and cons per candidate.

The skill triggers by itself when you want a new reusable tool to exist, and stays silent on small tasks such as a one-off script, a fix or a new flag. mouseketool has no LLM of its own: your agent's model does the judging.

You need Node 24 or later, pnpm, and a GitHub token: either GITHUBTOKEN, or being logged in with gh auth login.

Claude Code. The repository is a plugin:

opencode. 1. Copy skills/mouseketool/ into a skills directory, such as .opencode/skills/ or ~/.config/opencode/skills/. 2. Add the server to opencode.json, as in opencode.example.json, with the absolute path to dist/server.mjs.
