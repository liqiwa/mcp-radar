About codindex

tree-sitter 解析 AST，把函数、调用图、模块依赖图、控制流图存进单个 SQLite 文件， 通过 32 个 MCP 工具供 AI 查询。让 AI 不必 grep、不必逐文件 Read， 就知道仓库里有什么、谁调用了谁、改一处会波及哪里。

- 本地优先 — 不调 LLM API、不上传源码、无遥测 - 结构化 — 调用边由 AST 解析得出，不是正则猜的 - 快 — 自扫描 38 文件 / 145 函数 / 7,570 调用边，3.4 秒

以 MCP server 接入 Claude Code、Cursor、VS Code、Windsurf、Codex 及任何支持 Model Context Protocol 的 client。代码搜索与代码导航（code navigation）走 SQLite FTS5， 语义簇走调用图 BFS，产物是一张可查询的代码图（code graph）。

agentic coding 的关键瓶颈不是模型能力，而是给它看什么：整仓塞进上下文会爆，靠 grep 又只能拿到碎片。Codindex 把仓库索引成一份可复用的 repo index，让 AI 按需取结构化 code context——而不是把几万行源码反复喂进去。

Codindex — a local-first code indexing, codebase indexing and code intelligence server for AI coding agents, doing static analysis and code analysis locally. Parses any repository with tree-sitter into a structural static-analysis index (function inventory, call graph and call chains, dependency graph, control-flow graph, impact analysis, dead-code detection) and serves it over MCP. Code search and navigation run on SQLite FTS5; semantic clusters come from call-graph BFS. 32 tools · 6 languages · MIT · no telemetry.

你想知道 用 grep 的做法 Codindex --------- 谁调用了 scanProject？ 正则匹配，跨文件/别名/方法调用全靠猜 getcallgraph 改这个函数波及哪些文件？ 手工顺藤摸瓜，容易漏 getimpactanalysis 这个模块依赖了谁，有循环吗？ import 正则，路径别名解析不了 getmoduledeps 哪些函数从没被调用过？ 基本做不到 getdeadcode 有没有可复用的现成实现？ 靠记忆和全文搜索 getreusereport 这个函数的分支和循环长什么样？ 读源码脑补 getcfg

在 CodeGraph 仓库（146 个 TS 文件）上实测：AST 统计到 1,926 个函数， 让 Agent 用 grep 手工统计只得到约 951 个——差一倍，且 grep 拿不到调用关系。
