About Dep-Vet

Check a package's risk before it enters your lockfile.

dep-vet npm express@5.3.0 dep-vet pypi requests==2.31.0 dep-vet audit package-lock.json dep-vet guard --check -- npm i express

npm install runs code, and so does a Python sdist build. dep-vet reads public registry metadata and OSV advisories for npm, PyPI, crates.io, Go modules, JSR, RubyGems, NuGet, Maven, and Composer, then tells you what a package will do at that moment: whether it runs install-time code, how old it is, who published this version, whether its name is one typo away from a package you trust, what vulnerabilities apply to this exact version, and whether it is deprecated. Every finding links to the raw evidence it came from.

No account, no API key, no telemetry, no score out of 100. One binary for the CLI, agent hooks, and MCP.

dep-vet npm audit Dependabot ------------ Question should this tarball run on my machine? is an installed version vulnerable? is an installed dependency outdated or vulnerable? Moment before npm install after install after commit Input a package name you are considering a lockfile a repository

The gap is the moment trust is granted. The axios@1.14.1 compromise added a single dependency whose only job was a postinstall hook — invisible in package.json, transitive, and already running by the time an audit exists.

Releases are checksummed (sha256.sum), carry SLSA provenance attestations, and are built for Linux (glibc and static musl), macOS (aarch64 and x8664), and Windows x8664.
