About devkb

A knowledge graph of your repository for software development agents. Agents answer "what calls this, what breaks, which tests" in one step instead of searching file by file: 55% cheaper, with better answers, in our benchmark.

- A graph built from your source and git history: functions, calls, tests, routes, errors, configuration, commits, pull requests, tickets (ontology). - Packs: one command answers a whole question (who calls this, what breaks, which tests to run), each item with the source line that proves it, and a statement of what the graph could not see. - An MCP server giving agents the same answers as tools, for Claude Code, Codex and any MCP client.

Everything runs locally: devkb reads files and runs git, never your code (unless devkb.json opts in), and the graph never leaves your machine.

Language Status What devkb understands --------- Python ✅ Supported functions, classes, calls (through imports, re-exports, typed objects, base classes), tests, FastAPI/Flask routes, raised and logged errors, environment variables; every pack TypeScript, TSX 🟡 Partial functions, components, classes, and the HTTP calls they make to backend routes; not calls between them JavaScript (.js, .mjs) 🟡 Partial as TypeScript C ✅ Supported classes, structs, interfaces, records, methods, constructors, properties, local and extension methods, calls (same type and bases, this/base, typed receivers, static Type.M(), new T(), extension methods chosen by receiver type and argument count), xUnit/NUnit/MSTest tests; every pack.
