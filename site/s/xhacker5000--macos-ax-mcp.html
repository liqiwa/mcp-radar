About macos-ax-mcp

A single-binary, zero-dependency MCP server that lets a local coding agent (Claude Code, Antigravity, any MCP client) see and operate the Chrome you are actually using — every tab, the live DOM, console, network — plus the native macOS UI around it. No browser extension.

Accessibility is a means, not the goal. The goal is simple: when I ask the agent "look at this page", it should see what DevTools sees in the browser I already have open, with my logins, my tabs, my state. Everything in this tool serves that sentence.

1. Open source because of trust. A tool that can read every logged-in tab you have should not be a black box. The whole thing is ~4.2k lines of Swift with zero third-party packages, so you can read all of it in an evening and build it yourself instead of trusting a binary. 2. Talk to the platform directly, skip the middlemen. Browser extensions sit in a sandbox, cap payload sizes, need their own login, and disconnect. Chrome already ships a first-class automation protocol (CDP) and macOS already ships one for native UI (AXUIElement). This tool speaks both natively. 3. Deterministic, not visual. No screenshots-then-guess loops, no OCR. Every action is a state machine over real protocol state, with an error code and a step trace when it fails. Screenshots exist for you, not for decision-making. 4. Your tabs are yours. Reading is free. Anything that changes a page you opened (click, type, navigate, scroll, hover, drag, upload, close) is refused with ERRUSERTABPROTECTED unless the agent passes confirmusertab: true, which it may only do after you said yes.
