About memlite-mcp

A local-only MCP server and command-line manager for persistent, searchable agent memory. It uses libSQL for SQLite storage with native vector search and FastEmbed to generate ONNX embeddings on the device.

AI agents are stateless by design. Without persistent memory, an agent loses the decisions, failed approaches, and project conventions worked out in previous sessions. For a quick, self-contained task, that is fine. For an evolving codebase or an ongoing investigation, it means repeated work: the agent keeps rediscovering things, and you keep re-explaining them.

There are ways to give agents memory, but I wanted one with fewer trade-offs:

- Markdown files are easy to read and edit, but semantic search, proper structured metadata, relations, and confidence decay need something beyond plain text. - Cloud services can offer those features, but I prefer to keep memory on my machine, without another account or a hosted service dependency. - Self-hosted and local tools get closer, but I did not want containers, a separate database server, or another language runtime or package manager. - Standalone binaries fit the deployment model, but the ones I found did not combine the storage, retrieval, and memory features I wanted. - Harness-specific plugins can integrate deeply with one tool, but I wanted memory that could stay with the project no matter the tools.

The goal was simple: a tiny, fast, harness-agnostic local MCP server. Something useful from the first working build, without a whole stack to maintain or needless complexity.
