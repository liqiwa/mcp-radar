About VulnDog

VulnDog is a companion for active vulnerability hunting: you send the requests, it tells you which of them look like something worth chasing.

It runs as a local proxy on your machine, watches the traffic you route through it, and scores each request against an offline knowledge base of 456k CVE/CWE/exploit records. Everything it surfaces is an advisory candidate, never a finding — it flags a request as matching a known pattern, and confirming whether that matters is still your job. It never issues requests of its own.

Zero dependencies, stdlib Python, local Ollama embeddings for semantic matching, no cloud by default, MIT licensed.

Status: the capture → analysis pipeline, config v2, scope/SSRF rail, MCP server, AI-provider layer, and the db store-management surface are shipped (src/vulndog/), unified behind the vulndog console entry (M2.5): the observing proxy, timestamped run folders, redaction-before-persist, the offline matching engine, and vulndog db build / info / verify (M3.1) all work today via vulndog … (or python -m vulndog …). The CI/release workflow scaffolding is in place (M3.3), the docs are finalized (M3.2), and the independent-extension validation is shipped (M3.4 — stranger walkthroughs, re-proven by permanent offline tests): all milestones M1.1–M3.4 are delivered. Still planned (see PLAN.md for the milestone table): the first public release — no store ships in the tree yet and there are no releases (store distribution awaits the GAP-1 decision).
