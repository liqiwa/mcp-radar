About rw-modding-mcp

仓库 https://github.com/GMBOXMOD/rw-modding-mcp，变更见 CHANGELOG.md。

工具 作用 ------ lookupkey 按节查键，默认短释义与例子，保留来源、资料冲突和约束；完整资料按需取 searchsource 批量搜 Java 源码，带有限上下文、分页、空结果诊断和内容预算 getref 按主题和名称查事件、函数、枚举、内存类型与规则；无参数保留完整速查表 lint 静态检查文件或目录；支持批量 paths，未改动的文件复用上次结论 explainactions 画 事件/autoTrigger/按钮 → 动作 → alsoTriggerAction 的调用图，标 repeat、条件、memory 读写

查多个键用 lookupkey(keys=[...])，检查多个文件用 lint(paths=[...])。 批量查询能减少模型往返，精简输出能减少进入上下文的资料量；实际费用取决于客户端、模型和缓存。 本地 lint 缓存只节省检查时间，不是模型的提示词缓存。MCP 也不能限制客户端的 Bash、子 agent 或模型请求预算。

- lookupkey 默认 detail="brief"：每个节最多一条短释义/例子，最多展示三个节。 长说明标 truncated，过长的例子用 exampleomitted 标明省略，不返回半段配置；未展示的节标 entriesomitted。 约束、资料冲突和重要说明保留。 section 接受 action、[actionbtn] 或 M 等节名/章节字母。 sectionmatch=false 表示资料没有确认指定节的用法，不等于该键在引擎里绝对不可用。 一次最多 32 个不同的键，重复输入只查一次；count 是去重后的数量，requestedcount 是输入数量。 - 返回形状变化：默认模式不再返回原始 csv / cn 数组，改用 entries；依赖原始字段的程序 请显式传 detail="full"。旧的位置参数保留，完整模式保留原有原始资料字段。 - searchsource 默认 10 条匹配、前后各 2 行（contextlines 可设 0–5）。 patterns 一次最多 8 个不同的查询，同一行匹配多个词只返回一次，计数见 bypattern。 mode="literal" 按原文匹配，找 %{ 就直接传 %{，不要写 %\{。 正则使用 mode="regex"；旧的 regex=True 仍可用，但不能与 mode="literal" 冲突。 pathfilter 是路径子串而非 glob。空结果看 reason / hints，不会擅自改模式或扩大范围。 - 搜索的 maxchars 默认 8000，范围 1000–20000，限制 matches 的紧凑 JSON 字符数， 不包含结果元数据，也不是 token 数。数量或字符预算达到上限时，用 nextoffset 作为下次的 offset。 超长匹配行/上下文会标明截短；分页只在进程内源码索引不变时稳定，重新反编译后需重启服务。 - getref() 无参数仍返回完整速查表。常用主题：events、functions、enums、memory、 sections、rules、mustpair、hardconstraints。name 按名称筛选，需同时指定 topic。 这轮只查询已有资料；没有新增教程模板，也不把“名称收录”当作运行时语义已验证。
