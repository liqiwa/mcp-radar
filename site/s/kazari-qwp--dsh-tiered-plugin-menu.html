About dsh-tiered-plugin-menu

让每个工作区、每个会话都能独立开关 DSH 插件、MCP 和 Skill，并使用各自不同的配置。

比如，只在写代码的工作区启用某个插件，在其他工作区关闭；同一个插件，在会话 A 使用配置 A，在会话 B 使用配置 B。直接从侧栏的小插件按钮打开菜单，在「设置」中使用原插件的配置界面。

配置按 客户端 → 父工作区 → 子工作区 → 会话 逐级继承，支持任意深度的工作区树。没有单独设置时沿用上级，需要时在工作区或单个会话里覆盖。

同一套核心支持桌面/Web、dsh-TUI 和 dsh-go。各包独立版本、独立发布；兼容的核心修复只需发布核心包，无须同步发布三个界面。

包 职责 --- --- dsh-tiered-plugin-core 分级继承、插件实例、依赖、MCP 与 Skill；由界面自动依赖 dsh-tiered-plugin-menu 原桌面/Web 菜单，保留原包名和配置路径 dsh-tiered-plugin-tui 终端侧栏面板；使用 TUI 宿主 React 与对话框 dsh-tiered-plugin-go dsh-go 原生菜单，并按会话转发其他原生插件的界面注册

挂在同一 DSH 宿主的界面共用一份核心和实例。 关闭其中一个不会影响其他界面或后台任务；最后一个持有者退出才释放核心。分别启动的 DSH 进程各有自己的运行实例，不能仅靠共用文件夹实现内存共享。

三端都提供插件 / MCP / Skill、本级 / 下级默认、继承 / 启用 / 关闭和配置编辑。桌面继续复用插件原设置页；TUI 逐字段编辑，手机使用 JSON 表单。详见 TUI、dsh-go 和 架构与验证。已验证隔离虚拟机中的实际 TUI/Web，以及连接虚拟机后端的 Android 官方 APK；包括界面操作和完整冷启动，见 测试截图与范围。
