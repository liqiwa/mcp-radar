About backwire

Reverse WebSocket bridge for remote terminal and desktop operations.

Embed directly in a FastAPI backend, or run as an authenticated Streamable HTTP / stdio MCP server.

[!CAUTION] Enabling --allow-shell, --allow-write, or --allow-input grants the connected model or caller the corresponding privileges of the current OS account. - Clients start in read-only mode (read, plus screen on --kind desktop). Do not enable --allow-shell for an untrusted model or user. - Use a dedicated low-privilege OS account and a long, unique token per device. - Terminate TLS (wss://) at a trusted reverse proxy on public networks; do not expose bare ws://. - /mcp requires a dedicated BACKWIREMCPTOKEN separate from device tokens and rejects requests when unset.

backwire connects machines behind a LAN, NAT, or container (without public IPs, inbound ports, or VPN/TUN interfaces) to a hub over an outbound WebSocket. An embedded FastAPI application or an MCP client routes explicitly authorized operations back to each connected device.

- Two integration modes: mount createwsrouter inside an existing FastAPI backend (without installing mcp), or run backwire-server (Streamable HTTP /mcp) or backwire-mcp (local stdio). - Standalone device script: copy client/backwireclient.py to any Python 3.9+ machine; headless mode depends only on websockets. - Access controls & logging: per-device tokens (wildcard disabled), capability checks on both hub and client, --workdir path restriction for file APIs, and redacted JSONL audit logging.
