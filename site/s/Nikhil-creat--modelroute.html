About modelroute

ModelRoute: Smaller Models. Bigger Impact. AI Project 5 by Nikhil Chary Sriramoju (GitHub · LinkedIn)

A working LLM routing system. A trained classifier predicts whether a support request needs a large model; easy requests go to a small, cheap model and hard ones to a larger one. Answers are grounded with RAG, near-duplicates are cached, PII and prompt injection are guarded, weak answers escalate, and every request is logged so cost, latency and fallback rate are measured, not guessed.

Quick start (about 2 minutes, no API keys needed)

Open http://localhost:8000 for the site wired to the live API, or /docs for the OpenAPI page. For real answers, copy .env.example to .env, add free Groq and Gemini keys and drop LLMMODE=mock. Without keys the responses are labelled provider: mock (extractive answers from the knowledge base).

How a request flows guard (injection block, PII redaction) → semantic cache → RAG (TF-IDF over kb/) → router (p(small is enough) vs per-mode threshold) → LLM (Groq 8B or Gemini, with failover and circuit breaker) → judge (weak answer escalates to the large model) → human review queue for uncertain cases → SQLite log. Each response includes a trace of these steps.

API Endpoint Purpose ------ POST /route {text, mode: fastcostquality, visualcomplexity?} returns answer, model, provider, cost, trace GET /stats Real request count, cost saving vs always-large, latency, fallback and cache rates GET /review, POST /feedback Human-in-the-loop queue and ratings GET /health, GET /config Status, modes and prices
