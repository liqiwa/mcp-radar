About iphone-control

Let an AI agent operate a real iPhone plugged into a Linux machine or a Mac — one Rust binary, no Xcode, no paid developer account, no jailbreak.

🚀 Quick Start &nbsp;·&nbsp; 📖 Docs &nbsp;·&nbsp; 📦 Releases &nbsp;·&nbsp; 🐛 Issues

[!NOTE] Early release (0.x). Verified with an iPhone 15 Pro Max (iOS 27.0.1) on Linux and macOS (Apple Silicon), and an iPhone 12 mini (iOS 26.4.1) on Linux. Other models and iOS 17+ should work but are untested — reports are welcome. The CLI, doctor output and MCP tool results are currently in Simplified Chinese; agents handle this fine.

AI agents can drive browsers and desktops, but a real iPhone is harder: Apple's automation tools need a Mac and Xcode, and the open-source alternatives come as separate pieces that each need their own setup, signing and babysitting.

iphone-control does it all in one Rust binary on Linux or macOS, built on idevice, Impactor and WebDriverAgent. A long-running daemon owns the phone — tunnel, HID session, WebDriverAgent session — and exposes it to Claude Code or any MCP client. It succeeds iphone-control-toolkit and keeps its MCP tools compatible.

- See and touch the screen: screenshots with region zoom, tap, swipe, long-press, text input (including Chinese), hardware buttons - Work with UI elements: read the element tree, tap by text (on a part not covered by floating bars or the keyboard), launch and close apps, open URLs, wait for text to appear - Fewer round trips: any action can return the resulting screen once it has settled, flagging pages still loading and blocking alerts; iphonebatch runs up to 20 steps i
