About agent-2pc

Two-Phase Commit & Compensating Journaling Engine for AI Agent Tool Execution

Engineered for autonomous coding agents, tool orchestrators, and developer harnesses. Bringing database ACID transactional finality to agent tool execution with zero dirty state, sub-2ms transaction latency, and deterministic crash recovery.

Autonomous coding agents (Hermes, Claude Code, OpenCode, SWE-Agent) operate across inherently non-transactional primitives: - Filesystem mutations: patch, writefile, directory creation. - Subprocess commands: cargo test, npm run build, database migrations. - Remote APIs: Issue trackers (Linear, Jira, GitHub), Slack notifications, payment leases.

When an agent executes a 5-step task and encounters an unexpected failure at step 4 (a compiler error, test assertion, or API rate limit), existing frameworks rely on prompt-level Sagas where the model is asked to "clean up its work".

The Result: 1. Hallucinated Rollbacks: The LLM forgets which files it touched, applies inverted diffs to the wrong line numbers, or deletes untouched user files. 2. Dirty Repositories: Syntax errors and half-baked imports remain committed in the user's working tree. 3. Orphaned Cloud State: Issues marked "In Progress" or API tokens remain dangling in third-party services.

agent-2pc solves this by introducing a formal, crash-consistent Two-Phase Commit (2PC) protocol with an append-only Write-Ahead Log (WAL) for AI tool pipelines.
