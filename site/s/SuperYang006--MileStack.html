About MileStack

不用翻找过期的 TODO 和历史对话，也能让开发者与编程 Agent 始终知道项目做到哪了、接下来该做什么。

MileStack 把项目进度和任务上下文统一保存在本地，让开发者与编程 Agent 始终基于同一份项目状态协作。它让每个新会话都能可靠回答三个问题：项目目前进展如何？现在正在做什么？下一步该做什么？

MileStack 目前处于早期 V0 阶段，面向本地开发工作流。项目数据始终保存在你自己的机器上。

开发者通常会先与擅长深度推理的模型讨论需求和方案，但讨论结论很容易停留在对话里。随着项目在不同会话、模型和开发者之间切换，真实进度又会继续散落到 TODO、计划文档和交接记录中。这些信息很快就会互相矛盾，新的 Agent 必须先重新拼凑项目上下文，开发者也得反复确认哪份计划才是最新的。

- 开发者可以在一个页面看到当前工作、待办顺序、阻塞、审核项和最近完成的任务； - 编程 Agent 有任务 ID 时直接读取指定任务；没有任务 ID 时通过 MCP 查询项目状态并选择队列中第一个可领取任务，然后建立本轮执行权、记录进展并留下交接信息； - 任务依赖和执行凭证明确展示哪些工作可以开始，并避免两个会话同时执行同一任务； - 每轮审核都绑定到确切的 Git commit，高风险工作仍由开发者把关； - 所有数据都保存在项目本地的 SQLite 数据库中，不需要账号、云服务或远程数据库。

1. 开发者与擅长深度推理的模型讨论需求和方案，直到双方确认目标与边界。 2. AI 调用 MileStack，将已经确认的结论整理成结构化任务，而不是让开发者逐条手工录入。 3. 开发者检查 AI 创建的草稿任务，确认风险、依赖和执行顺序。 4. 有任务 ID 时，实施 Agent 直接读取指定任务；没有任务 ID 时，它先查询项目状态，选择 next 中第一个 runnable = true 的任务，再通过 starttask 建立本轮执行权。 5. 实施 Agent 记录阶段成果、阻塞和交接上下文，并以固定 Git commit 提交。 6. 开发者将任务 ID 发送给独立审核 Agent；审核 Agent 通过 startreview 建立审核权并检查制品。 7. 审核结果进入 MileStack，页面和下一个被分派的 Agent 会话随即看到最新状态。

MileStack 需要 Node.js 22 或更高版本，以及请确保项目已初始化为 Git 仓库。

如需配置其他支持项目级 MCP 的客户端，可以把 codex 替换为 claude、cursor、grok 或 opencode；也可以重复传入 --client，一次配置多个客户端。AGY（Gemini CLI）使用动态项目发现，需要进行一次手动全局注册，详见用户指南。
