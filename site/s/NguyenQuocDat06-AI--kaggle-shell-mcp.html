About kaggle-shell-mcp

Turn free 12h Kaggle Dual-T4 GPUs into live, stateful remote terminals & detached job runners for AI Agents via MCP.

Tiếng Việt (Vietnamese Guide) · Architecture Spec (VN) · Contributing

Kaggle offers ~30 hours/week of free Dual NVIDIA Tesla T4 GPUs (2 × 15 GB = 30 GB VRAM), yet its official API (kaggle kernels push) only supports fire-and-forget batch runs. Existing community scripts either: - Push static notebooks and wait blindly for completion, or - Require manually pasting ngrok tokens into a browser cell, installing openssh-server, and fixing broken CUDA/LDLIBRARYPATH variables by hand.

kaggle-shell-mcp (CLI command: kgsh) bridges the gap in one zero-setup MCP server: - Zero Extra Accounts Required: Needs only KAGGLEUSERNAME and KAGGLEKEY (KGAT... bearer token or legacy key). No ngrok account, no VPN client required (optional Tailscale userspace mode is also supported). - 100% Native CUDA Environment: Injects a pure-stdlib Python PTY & RPC daemon directly inside the Kaggle Kernel runtime—preserving Conda, PyTorch, PATH, and LDLIBRARYPATH out of the box. - Agent-First Execution Split: - termexec — Stateful /bin/bash PTY (preserves cd, export, virtualenvs) for fast interactive exploration and debugging. - jobspawn / joblogs — Process-group isolated background jobs that survive network drops, with automatic tqdm carriage-return (\r) compaction so progress bars never blow up LLM context windows. - Built-In Quota & Snapshot Watchdogs: - 11h40m Safe Drain: Sends SIGTERM at 11h35m so training loops flush checkpoints, then exits cleanly (exit 0) at 11h40m—ensuring Kaggle c
