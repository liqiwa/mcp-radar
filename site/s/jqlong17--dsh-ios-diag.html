About dsh-ios-diag

一个 DeepSeek Harness（DSH）插件，同时是一个 stdio MCP server 和一组命令行工具。 做三件事：在模拟器上把能测的尽量测完、给真机做一次尽可能全的取证、把结论变成可交接的报告。

真机测试是一次高成本事件：设备、接线、装包、复现、抓数、传回。人不在电脑边时，这一天就废了。

目标 做法 --- --- 装真机前尽量测完 模拟器上的内存曲线、类型下钻、日志、调用栈、pcap 解析、6 项体检 真机只跑一次 一次会话把内存/日志/崩溃/网络/栈都留下，离线分析（进行中） 结论能交接 固定六段报告 + 带绝对路径的粘贴消息，开发拿去就能查 不碰被测项目 只读；临时文件写 $TMPDIR 并即删；报告写在本仓库

形态 谁用 入口 --- --- --- DSH 插件 DSH 里的 Agent / 右侧栏面板 安装后出现 15 个 ios 工具 + 「内存」面板 MCP server Claude Code / Cursor / 其他 harness node bin/mcp.mjs（stdio） 命令行 人 / CI npm run health、npm run report、npm run handoff

不要把 MCP 再挂回 DSH：DSH 已经有同名原生工具，挂上去只会多出两份工具和第二个采样进程。

工具 平台 回答什么问题 --- --- --- iosmemtargets 模拟器 哪些模拟器开着、里面哪些 App 在跑（bundleId + pid） iosmemstart / iosmemstop 模拟器 开始/停止实时采样（默认 1s，保留最近 30 分钟） iosmemstatus 模拟器 当前/峰值/均值/增量、涨速、top 类别 iosmemdetail 模拟器 此刻按镜像、按区域标签的排行（谁在吃） iosmemmark 模拟器 在时间轴打点（配合报告对齐操作） iosmemrecord 真机 录一段内存曲线（Activity Monitor，约 1Hz），回放 iosmemtypes 真机 录一段 Allocations，按分配类型排行 live bytes（VM 预留单独算） iosmemlaunch 模拟器 启动 App ioslogquery 模拟器 最近 N 秒的统一日志（log show --style json），可 grep ioshangsample 模拟器 采 N 秒调用栈（sample），回答「卡住时在干什么」 iospreflight 模拟器 装真机前体检：6 项 pass/warn/fail + report.md iosnetanalyze 文件 解析 pcap → HTTP 请求/响应/WS 帧对象（tshark） ioseventsexport 模拟器 把样本/打点/日志导出成统一事件表 + 链接 ioseventsquery 文件 给 id / rpcId 查一跳邻居；链接分事实与推断 （非工具）报告/交接 命令行 npm run report / npm run handoff

平台说明：模拟器指 App 跑在 Mac 上的模拟器进程；真机指 USB 连接的物理设备； 文件指只处理本地文件，不需要设备。

1. 先 iosmemtargets，拿 udid + bundleId（或 pid）。不要猜 pid。 2. pid 优先，bundleId 兜底：传 pid 最快；只传 bundleId 会自动找。 3. 打点要贴着操作：iosmemstart → 操作 → iosmemmark("刚做了什么")。没有打点的曲线很难归因。 4. 别重复开采样：同一时间只保留一个采样环；再次 start 会清空上一轮。 5. 真机工具会重新 launch App
