About mcd-penny-pal

基于麦当劳中国官方 MCP（mcp.mcd.cn）· 只调只读接口算钱 · 零 Token 就能跑通全链路

券包只会乖乖写一句「中薯条买一送一」。它不会说：这张真能省 ¥13.5 哦。 它更不会说：旁边那张「王牌小食拼」看着更香，券面印着 ¥15.9，其实只能省 ¥6.1。

只要 Python 3.11+ 标准库。没有任何第三方依赖，不用联网，也不用麦当劳账号。

上面这几条命令读的是 fixtures/demo/ —— 2026-10-16 对 mcp.mcd.cn 的真实返回， 只脱敏了账号 ID、收货地址、手机号这些个人信息，券码、门店、价格一个字符都没动。 所以离线跑出来的结果，跟你自己连上账号跑是逐字一致的。

券池 接口 特点 --------- 麦麦省待领券 available-coupons → auto-bind-coupons 领取机会，没有有效期 我的券包 query-my-coupons 唯一带真实有效期的来源 当前门店专属券 query-store-coupons 唯一带 couponId / couponCode 的来源 门店定位 query-nearby-stores 用 beType + searchType，不是 address

- 临期预警只能以券包为数据源 —— 另外两路都给不出有效期 - 「已领取」不能再提示「可以领」 —— 领完券后可领池的 status 会全部翻转 - 同名券不能按名字去重 —— 实测有两张「巧克力味厚松饼猪柳蛋套餐」，一张 10-17 到期、一张 10-18，去重键必须带上到期时刻

券 原价 实付 真实省下 券面标注 --------------- 中薯条买一送一 ¥27.0 ¥13.5 ¥13.5 ¥13.5 9.9元中杯冰美式 ¥19.0 ¥9.9 ¥9.1 ¥9.9 王牌小食拼 ¥22.0 ¥15.9 ¥6.1 ¥15.9 ⚠️

看最后一行：券面标注 ¥15.9，实际只省 ¥6.1。谁按券面价排序，谁就会给你推错券。

create-order 下单 → query-order 追踪 → cancel-order 反悔。 下单是不可逆动作，门店、餐品、金额必须复述一遍让你确认过，才敢执行。

order-list 还原真实消费 + query-my-account 看积分（积分是另一种有保质期的钱）。 整单退款不计入消费；样本不足 3 笔时只报单数，不报客单价。

说句实话：这次实测账号的 order-list 返回 data: {}，没有可读的历史订单， 所以 M4 只完成了积分侧，消费统计暂时没法用真实数据验证。

这不是写在文档里的口号，是有断言守着的（tools/testcard.py / testvaluation.py）：

铁律 落地方式 ------ 绝不估算价格 所有金额必须来自 calculate-price / query-meals 返回。简报里每个数字都要能在输入里找到出处，测试会往简报里塞一个 ¥999.9 验证能否被抓出来 券必须从四路查全 四路合并去重，命名规范化后按「券名 + 到期时刻」匹配 券的价值要能反查 门店券里没有的券，价值记 0 并标注「无法估价」。部分可估时绝不说「这 N 张值多少」 不诱导消费 凑单反而更贵时主动说破，哪怕这意味着这一单不花钱

- 只讲能核到价的券 —— 门店券里没有对应条目的券，卡片上一个数字都不给 - 大数字只算最紧急那一组 —— 把「今天到期」和「T-3 内到期」混着算，会出现「今天到期 2 张」配「4 条清单」的错位
