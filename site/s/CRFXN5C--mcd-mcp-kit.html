About mcd-mcp-kit

麦当劳中国 MCP Server 的接入体检工具包 —— 30 秒确认你的接入到底通没通，以及为什么"看起来通了"其实是错的。

你可能以为 实际是 ------ 文档列了 33 个工具 tools/list 返回 35 个，多出的两个文档没写 鉴权失败会统一返回 401 两种状态码、两种 body：无 Token → 403 + 业务信封 code=0001；错 Token → 401 + 纯文本（不是 JSON） 照文档写 query-partystore-date 正确名字是 query-party-store-date，照抄调用必失败（返 JSON-RPC error，不是 404） 算价返回 0 元 = 商品不可售 是字段名传错了（code vs productCode），接口不报错 价格 5900 = 5900 元 单位是分，= 59 元 query-my-coupons 能判断这单能用哪张券 不能，它不做门店校验；要用 query-store-coupons

doctor.py 把这些一次性检查完，并给出一份可直接粘贴进 issue 的报告。

python doctor.py --probe-auth 的实际输出（2026-10-23）：

断网、拒连、DNS 失败这类情况不会抛 traceback —— 已经收集到的结果照常打印， 失败项给出最近一次错误原文，退出码 2。

命令 作用 ------ python doctor.py 接入体检（只读，无副作用） python doctor.py --probe-auth 额外探测「无 Token / 错 Token」的真实状态码与 body 形态 python doctor.py --json 机器可读输出，便于接 CI

doctor.py 退出码：0 = 全部通过（可能有 WARN）；2 = 存在问题（有 FAIL）。 参数写错时 argparse 也返回 2，若要在 CI 里区分，请用 --json 读 ok 字段。

服务端会把「字段说明 + 原始响应」拼在同一段文本里返回，--json-only 只保留后者，方便接管道或 jq。 mcdmcp.py 已内置两种非标准错误形态的处理，退出码：0 正常 / 1 用法错 / 2 鉴权或协议失败。

完整版见 PITFALLS.md，每条都带「现象 / 原因 / 正确做法 / 复现方式」。

坑 ------ 1 工具数 33 vs 35（query-promotions、query-survey-coupon 文档没写） 2 文档工具名拼错：query-partystore- → query-party-store- 3 鉴权失败状态码有两种：无 Token 403 + 业务信封、错 Token 401 + 纯文本（没有统一错误结构） 4 calculate-price 字段名传错 → 静默 0 元（但 0 元不一定是传错，别只归因这一条） 5 金额单位是分 6 特调 modification 必须整组传（selectedKey / unselectedKey） 7 query-store-coupons ≠ query-my-coupons（后者不校验门店） 8 到店自取（beType=1）不能传 beCode 9 积分兑换多商品必须串行排队下单 10 order-list 只有最近 10 单 11 主题派对商品可能在「品鉴会」类目（1625），不在主题类派对 12 抽奖有独立频控，且不要自动重试 13 list-nutrition-foods 的 data 是字符串（内含 [160]{字段列表}: + CSV 行），不是数组
