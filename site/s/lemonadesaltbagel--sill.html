About sill

Bash for coding agents on native Windows. sill is a drop-in bash.exe: a Bash interpreter (a fork of brush) with a Windows adapter built for the way agents run commands. It needs no Git, MSYS2 or WSL. Point Claude Code, opencode or Codex at it, or add it to Codex CLI or Gemini CLI as an MCP server, and the agent's shell commands behave the way the model expects from Linux, on Windows' own programs and files.

An agent on Windows loses most of its failed commands at the boundary between the shell and Windows, not in its own reasoning:

- Arguments: and quotes get re-expanded or mangled on their way to .exe and .bat programs. - Paths: /c/... and C:\... forms get mixed up. - Encoding: non-English text turns to mojibake. - Console windows: one flashes up per command. - Background servers: they hold the harness's output pipe until it times out. - Missing tools: make, rg, ps, lsof aren't there.

sill takes each of these on directly, with a test for each.

All measured on Windows 11 with the Git Bash that ships with Git for Windows as the comparison.

Conformance suite (sill-bash-tests): 56 cases, run through bash.exe -c and through the MCP server (56/56 both ways) covering what agents rely on, each with the reason it matters. Areas: arguments to native programs, paths, encoding, line endings, processes, size limits, ! scripts, tools, errors.
