About speclok

spec-as-annotation for Java. Your spec lives in the code, and the compiler enforces it. Just as javac rejects a bad @Override, speclok makes it reject an incomplete @Spec.

speclok is a tiny, dependency-free annotation library and CLI for Java. It turns the specification of a piece of code into an annotation that sits on the class and method it governs. From that single source of truth, speclok:

1. generates the documentation, the per-task briefing and the task index, 2. enforces the contract at compile time (an incomplete spec is a compile error), and 3. serves the whole thing to an AI coding agent through hooks and an MCP server.

No separate spec files. No .md/.yaml to drift. The spec is versioned with the code, in the same commit, because it is the code.

Write an incomplete @Spec (empty objective, no @AC, an @AC missing then) and your IDE underlines it in red - a standard compile error, anchored at the exact line:

You have a large, old codebase with little or no documentation. Nobody holds the whole thing in their head, the rules for what-can-change-where live in people's memory, and letting an AI agent loose in there is a risk. speclok is for exactly that: it turns the guardrail from tribal knowledge into a rule the compiler enforces.

- No docs, and no time to write them. You do not stop to document the repo. The spec accretes where the work happens: each time you touch a method, you annotate that method.
