About lasagna

Test your RAG components against a real stack, not a toy baseline. Then give that stack to your agent.

Code for Retrieval Augmented Generation Compositionality Ido Levy1,2 · Segev Shlomov1 · Leshem Choshen1,2 1IBM · 2Weizmann Institute of Science

Quickstart · Compare a component · Give your agent RAG · Docs · The paper

A real run with the idle waits cut: write a reranker, sweep it against a built-in, and get a Holm-corrected verdict.

Most RAG results are reported one component at a time. A new reranker is measured against a baseline with no query augmentation, no agentic loop, and an old chunker, because building the rest of the stack just to run the comparison is more work than the contribution itself.

That makes published gains hard to add up. If a reranker claims +4 NDCG and a query expander claims +3, you cannot tell from the papers whether stacking them gives you +7, +4, or -1. Lasagna exists to make that question answerable.

All eight stages take effect. Five at query time (reranker, queryenhancer, embedder, retriever, agenticpipeline), two at ingest (chunker and documentprocessor), and generator, which writes the answer from what retrieval returned.
