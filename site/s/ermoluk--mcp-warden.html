About mcp-warden

A local-first credential broker for the Model Context Protocol — lets any AI coding agent (Claude Code, Cursor, Cline, Codex, Continue, Zed) take real actions without ever seeing your secrets.

The agent calls high-level tools (proxyhttp); mcp-warden injects the secret server-side, executes the action, and returns only the result. Your context window stays clean. A leaked transcript leaks nothing useful.

1. You store a credential once in the OS keychain via the mcp-warden CLI. 2. You define presets — named, scoped actions (e.g. github-read, stripe-charges). 3. The AI agent connects to mcp-warden as an MCP server (stdio). 4. When the agent wants to act, it calls proxyhttp with a preset name and a path/method. 5. mcp-warden validates the request against the preset's allow-list, injects the credential, executes, and returns only the response. 6. Sensitive presets trigger an approval prompt: a native dialog on macOS and Windows, a desktop notification with Approve / Deny on Linux, or a Telegram message on any OS — where /lock also works as a kill switch from your phone. Opt in to time-boxed approvals per preset so one OK can cover a short burst of follow-up calls without re-prompt spam. 7. Every action lands in a local SQLite audit log — including a windowed decision for calls authorised by an active approval window, a refused decision (with the raw requested path or command) for calls the allow-list turned away, and a failed decision when the approval prompt could not be shown.
