About open-anywhere

Open Anywhere 让人用一句话描述此刻的需要，由云端编码 Agent 当场生成一个可运行的 Web 应用，投到身边的屏幕上，并继续用语音操作它：

我们有三个人，想比较一下每个人的知识储备量，请你做个电影知识竞赛 App，你来主持，放到电视上。

应用不在菜单里，是被当场写出来的；玩法不在代码里，是被当场理解并驱动的。有块屏幕，就能开场。

参赛议题：灵矽应用 —— 通过 DLNA 把画面投到电视上，并通过语音控制 code agent 进行编程开发（AirPlay 为后续扩展）。

现场 你说 屏幕上长出来什么 --- --- --- 家庭知识竞赛 “一家三口，十道自然知识题，你出题、你记分。” 题目、抢答顺序和三人的比分；一家人一起上桌，不用留一个人全程操作 做饭 “今晚做糖醋排骨，把步骤和计时放到屏幕上。” 分步菜谱、火候提醒和倒计时；手上沾着油，说一句“下一步”就翻页 陪伴 “把你自己放到电视上，陪我们聊会儿天。” 智能体以形象出现在屏幕上，随对话做出表情和动作，声音变成一个在场的角色 大富翁 “我们四个想玩大富翁，棋盘上电视，你来当银行。” 棋盘、骰子、地契和资产表；掷骰子、买地、结算都由它接手 科普读物 “给孩子做一本讲恐龙灭绝的书，能一页页翻。” 图文分页、语音翻页，读到哪儿都能停下来问一句“为什么”

这些应用没有一款是提前开发的，也不需要进菜单。场景不在代码里，在你那句话里。 想玩什么、想学什么、想做什么，甚至只是想聊会儿天，说出来就行。

灵矽没有屏幕，但中国有 4.39 亿台电视。只靠预设技能，语音硬件最终都会变成一台会说话的故事机；能当场写应用、投到身边的电视上，它就从玩具变成了现场的活动服务——每一块电视，都可以是灵矽的屏幕。

太具体、太短、太不值钱。但这样的场合每天都在发生：民宿今晚要接待客人，轰趴馆这周要办活动，他们本来就在为“这一场”付钱。我们按场定价：朋友局 199 元一场，商家单场 399 元、包年 3,999 元，多带来 2–3 场活动就回本。

成品在出厂时就做完了，用户几天就能摸到边界，新鲜感过去就放进抽屉。产能是“你需要什么，它当场生产什么”：每遇到一个新场合，它就重新长出一个应用——在孩子房间是亲子问答，在客厅是三人竞赛，在店里是活动大屏。它可能一个月才用一次，但可以在客厅待五年。

生成只是第一步：画面要上屏，几个人要一起玩，语音还要能继续操作——开始、下一题、查比分。四个人、四个当场生成的应用、一场之内全部玩完，中途还切换过。付费与复购尚未验证。

商业规划见商业计划书：市场机会、成品与产能的商业模型、七个年龄段需求地图、定价体系、第一周闭环、单元经济与三年目标。市场背景、产品定位与收费模式的完整论证见商业策略。

你说一句话：几个人、什么主题、投到哪块屏。系统听懂它，把它变成一个能跑的应用，再把画面送到电视上——说话 → 听懂 → 生成应用 → 上屏 → 继续用语音操作。

这一步 由谁完成 做什么 --- --- --- 听懂 灵矽（语音入口） 识别场景、人数、主题与屏幕，决定调哪个工具 编排 控制面 校验请求、调度构建、转发操作 写代码 AgentAPI 在隔离环境里生成应用并自测 上屏 Render 启动应用、采集画面、送出媒体流

生成的应用把每个操作都声明成 OpenAPI，控制面提供稳定的 MCP 工具，所以语音不只能创建它，还能在运行时操作它：开始、下一题、查比分，都是一次业务调用。
