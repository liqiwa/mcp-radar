About MC-Test

A dev-only Minecraft client mod (Fabric + NeoForge, Minecraft 26.3) plus an MCP server, so Claude Code (or any coding agent, or your own scripts) can drive a running Minecraft client the way Playwright drives a browser: open worlds, click GUIs, press keys, walk, mine, place, craft, fight, run commands, inspect blocks, entities and inventories, read logs and take screenshots. The main use is testing your own mods.

Documentation: https://mctest.coolerpromc.com/

- Loopback only. The control servers bind to 127.0.0.1. On the client, MCTest drives the game; on a dedicated server (optional, see Testing on a dedicated server) it exposes the server side. - Never ship it. Add it to your mod as a dev-runtime dependency (see below). It is not bundled into your jar or published POM. - Everything runs through vanilla code paths: input goes through Minecraft's own mouse/keyboard handlers and key mappings, and interactions go through MultiPlayerGameMode, so the server validates them as for a real player.

MCTest is published to https://maven.coolerpromc.com/releases/ as com.coolerpromc.mctest:mctest-fabric-26.3: and com.coolerpromc.mctest:mctest-neoforge-26.3:. The snippets below use that repository. If you're changing MCTest itself, run ./gradlew publishToMavenLocal and use mavenLocal() instead to pick up your local build.

Fabric (Loom), in your mod's fabric/build.gradle

localRuntime is Loom's dev-runtime configuration. transitive = false stops MCTest's own fabric-api / fabric-loader runtime dependencies from overriding your versions.
